# Аналіз проєкту StoryFlow

## 1. Загальний огляд
**StoryFlow** — це веб-додаток для відстеження оновлень манґи або коміксів. Проєкт має сучасну клієнт-серверну архітектуру з використанням Docker для зручності розгортання та розробки.

---

## 2. Технологічний стек

### Frontend (Клієнтська частина)
- **Framework:** React 19
- **Build Tool:** Vite 8 (забезпечує швидку збірку та HMR)
- **Мова:** JavaScript (ES Modules)
- **Стилізація:** Vanilla CSS (використовується модульний підхід до компонентів)
- **Компоненти:** Функціональні компоненти React з використанням Hooks.

### Backend (Серверна частина)
- **Runtime:** Node.js (версія 20-alpine у Docker)
- **Framework:** Express 5
- **База даних:** MongoDB (через Mongoose ODM)
- **Безпека:** Bcryptjs (хешування паролів), JSON Web Token (JWT для аутентифікації)
- **Інструменти:** Nodemon (для автоматичного перезапуску в розробці), Dotenv (керування змінними оточення)

### Інфраструктура
- **Docker:** Повна контейнеризація всього стеку.
- **Docker Compose:** Оркестрація трьох сервісів: `frontend`, `backend`, `mongodb`.
- **Persistent Storage:** Використання Docker Volumes для збереження даних MongoDB.

---

## 3. Структура проєкту

```text
StoryFlow/
├── backend/                # Серверний код (Express + MongoDB)
│   ├── models/             # Схеми даних Mongoose (наразі порожньо)
│   ├── index.js            # Точка входу сервера, підключення до БД
│   └── Dockerfile          # Конфігурація образу бекенда
├── frontend/               # Клієнтський код (React + Vite)
│   ├── src/
│   │   ├── components/     # UI компоненти (Header, Sidebar, UpdatesGrid)
│   │   ├── pages/          # Сторінки додатку (Home)
│   │   └── App.jsx         # Головний компонент
│   └── Dockerfile          # Конфігурація образу фронтенда
├── docker-compose.yml      # Налаштування запуску всіх сервісів
└── PROJECT_ANALYSIS.md     # Цей файл аналізу
```

---

## 4. Аналіз функціональності

### Поточний стан (Frontend):
- Реалізовано базовий макет сторінки `Home` з розділенням на контентну частину та бічну панель.
- Компонент `UpdatesGrid` відображає список оновлень (наразі використовуються статичні мок-дані: Наруто, Бліч, Ван Піс тощо).
- Використовується чистий та сучасний CSS для стилізації карток манґи.

### Поточний стан (Backend):
- Налаштовано базовий сервер на Express.
- Інтегровано підключення до MongoDB через URI зі змінних оточення.
- Створено каркас для майбутніх моделей даних та API ендпоінтів.

---

## 5. Docker Конфігурація

Проєкт повністю готовий до роботи в ізольованому середовищі:
- **MongoDB:** Працює на стандартному порту `27017`.
- **Backend:** Працює на порту `5000`, має автоматичний доступ до БД за внутрішньою мережею Docker.
- **Frontend:** Працює на порту `5173`, налаштований на зовнішній доступ через `--host`.

---

## 6. Рекомендації для подальшого розвитку
1. **Моделі даних:** Потрібно створити схеми у `backend/models/` для Манґи, Користувачів та Оновлень.
2. **API:** Реалізувати ендпоінти для отримання списку оновлень з бази даних замість мок-даних на фронтенді.
3. **Аутентифікація:** Оскільки залежності (JWT, Bcrypt) вже встановлені, варто реалізувати реєстрацію та вхід користувачів.
4. **Environment Variables:** Створити `.env` файл для бекенда (локально) для налаштування секретів JWT.
