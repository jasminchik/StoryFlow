# Аналіз та Звіт проєкту StoryFlow

## 1. Загальний огляд
**StoryFlow** — це веб-додаток для читання та відстеження оновлень манґи, коміксів та фанфіків. Проєкт реалізований як Fullstack додаток із використанням сучасного JavaScript-стеку та повною контейнеризацією через Docker.

---

## 2. Технологічний стек

### Frontend (Клієнт)
- **React 19** + **Vite 8**
- **Vanilla CSS** (компонентно-орієнтований підхід)

### Backend (Сервер)
- **Node.js 20** + **Express 5**
- **MongoDB** + **Mongoose**
- **JWT (JSON Web Token)** & **Bcryptjs** (Аутентифікація та авторизація)
- **Multer** (Локальне завантаження медіа-файлів)

### Інфраструктура
- **Docker & Docker Compose**: Сервіси `frontend`, `backend` та `mongodb`.
- **Persistent Volumes**: Збереження даних бази та завантажених зображень (`/uploads`) на хост-машині.

---

## 3. Структура проєкту (Станом на Етап 2)

```text
StoryFlow/
├── backend/
│   ├── config/
│   │   └── upload.js       # Конфігурація Multer (локальне сховище)
│   ├── middleware/
│   │   └── authMiddleware.js # Захист маршрутів (protect, authorize)
│   ├── models/
│   │   ├── User.js              # Користувачі
│   │   ├── Manga.js             # Тайтли (Манґа, Манхва тощо)
│   │   ├── Chapter.js           # Глави манґи (картинки)
│   │   ├── Literature.js        # Фанфіки/Книги (текст)
│   │   └── LiteratureChapter.js # Текстові глави
│   ├── routes/
│   │   ├── authRoutes.js        # Реєстрація та Логін
│   │   ├── userRoutes.js        # Керування юзерами
│   │   ├── mangaRoutes.js       # CRUD манґи + модерація
│   │   ├── chapterRoutes.js     # Керування главами манґи
│   │   ├── literatureRoutes.js  # CRUD фанфіків
│   │   └── literatureChapterRoutes.js # Текстові глави
│   ├── uploads/            # Папка для локальних медіа (ігнорується git)
│   ├── index.js            # Головний файл сервера
│   └── Dockerfile
├── frontend/ ...
└── docker-compose.yml
```

## 4. Реалізований функціонал (Етап 1 та 2)

### Основні модулі:

1.  **Аутентифікація та Авторизація**:
    - Реєстрація, логін, захист маршрутів через JWT.
    - Рольова модель: `user`, `author`, `admin`.

2.  **Керування контентом (CRUD)**:
    - **Манґа/Комікси**: Створення, редагування, видалення, завантаження обкладинок.
    - **Глави манґи**: Масове завантаження зображень (до 50 сторінок), автоматичне сортування.
    - **Література (Фанфіки)**: Текстовий контент, підтримка WYSIWYG структури в базі.

3.  **Медіа-система**:
    - Локальне збереження зображень у папці `uploads`.
    - Автоматичне створення унікальних імен файлів.
    - Статична роздача файлів для фронтенду (`/uploads`).

4.  **Система премодерації**:
    - Статуси: `pending`, `approved`, `rejected`.
    - Публічний каталог відображає лише схвалені твори.
    - Спеціальні PATCH-ендпоінти для адміністраторів.

## 5. API Ендпоінти (Головні)

| Метод  | Шлях                         | Доступ         | Опис                                   |
| :----- | :--------------------------- | :------------- | :------------------------------------- |
| **POST**   | `/api/auth/register`         | Всім           | Реєстрація нового акаунту              |
| **POST**   | `/api/auth/login`            | Всім           | Вхід та отримання JWT                  |
| **GET**    | `/api/manga`                 | Всім           | Список схвалених тайтлів               |
| **POST**   | `/api/manga`                 | Author/Admin   | Створення тайтлу (+ обкладинка)        |
| **PATCH**  | `/api/manga/:id/moderation`  | Admin          | Зміна статусу модерації                |
| **POST**   | `/api/chapters`              | Author/Admin   | Завантаження глави (+ масив сторінок)  |
| **GET**    | `/api/literature`            | Всім           | Каталог фанфіків/книг                  |

## 6. Технічні особливості Етапу 2

- **Docker Volumes**: Налаштовано монтування `./backend/uploads:/app/uploads`, що дозволяє зберігати завантажені картинки навіть після перезбірки контейнерів.
- **Mongoose Indexing**: Додано унікальні складені індекси для глав, що запобігає дублюванню номерів розділів у межах одного твору.
- **Data Integrity**: Використання `.populate()` для зв'язків між творами та їх авторами.

## 7. Наступні кроки (Етап 3: Фронтенд та UI/UX)

1.  **Глобальний стан**: Налаштування `Context API` або `Redux` для збереження даних авторизованого користувача.
2.  **Каталог та Фільтрація**: Реалізація пошуку, фільтрації за жанрами та типами на фронтенді.
3.  **Читалка**: Створення зручного інтерфейсу для перегляду сторінок манґи (вертикальний/горизонтальний скрол).
4.  **Текстовий редактор**: Інтеграція `Quill.js` або `TinyMCE` для авторів фанфіків.
5.  **Кабінет користувача**: Сторінка профілю з історією читання та доданими творами.
