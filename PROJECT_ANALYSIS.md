# Повний аналіз проєкту StoryFlow

## 1. Загальний огляд
**StoryFlow** — це масштабна Fullstack-платформа для читання та публікації манґи, манхви, коміксів, а також художньої літератури (фанфіків, книг). Проєкт поєднує в собі функціонал соціальної мережі для авторів та читачів, надаючи передові інструменти для управління контентом, взаємодії через складну систему коментарів та рейтингів, а також глибоку персоналізацію досвіду користувача через списки та аналітику читання.

---

## 2. Технологічний стек

### Frontend (Клієнт)
- **React 19**: Сучасна бібліотека для побудови інтерфейсу.
- **Vite 8**: Високопродуктивний інструмент збірки.
- **React Router 7**: Навігація та керування маршрутами.
- **SCSS Modules**: Модульна стилізація для уникнення конфліктів класів та підтримки чистих стилів.
- **Lucide React & React Icons**: Набори іконок для UI.
- **Recharts**: Побудова динамічних графіків активності користувача.
- **Context API**: Керування темами (ThemeContext) та глобальним станом авторизації.

### Backend (Сервер)
- **Node.js (Express 5)**: Швидкий та масштабований веб-фреймворк.
- **MongoDB + Mongoose**: NoSQL база даних зі складною агрегацією даних.
- **JWT (JSON Web Token)**: Безпечна аутентифікація.
- **Multer**: Завантаження та обробка медіа-файлів (обкладинки, сторінки розділів).

### Інфраструктура та DevOps
- **Docker & Docker Compose**: Повна контейнеризація всього стеку (frontend, backend, database).
- **Persistent Volumes**: Збереження даних бази та завантажених файлів.
- **Scripts**: Наявність скриптів для сидування даних (`seeder.js`).

## 3. Архітектура та структура проєкту

### Frontend (`/frontend/src`)
- **`components/`**: Велика бібліотека UI-компонентів. Включає складні модулі як-от `SearchOverlay` (глобальний пошук), `InteractionSection` (динамічні коментарі/обговорення) та `Header` із багаторівневою навігацією.
- **`pages/`**: 
    - **Home**: Головна сторінка з динамічними блоками "Новинки" та "Популярні", що автоматично формуються сервером на основі часу додавання та рейтингів.
    - **Catalog**: Потужний каталог із клієнт-серверною фільтрацією за форматом (Манґа/Манхва), статусом та жанрами.
    - **MangaDetails / FanficDetails**: Детальні сторінки з динамічними гістограмами оцінок, каскадним видаленням та можливістю додавання в персональні списки.
    - **Profile**: Багатофункціональний кабінет користувача. Містить інтерактивні фільтри списків читання, керування власними творами та динамічну візуальну аналітику (графіки прочитаних розділів).
    - **CreateManga / CreateFanfic**: Інструменти автора (CMS).

### Backend (`/backend`)
- **`models/`**: 
    - `User`: Дані користувачів, ролі, статси.
    - `Manga`, `Chapter`, `Literature`, `LiteratureChapter`: Ядро контенту.
    - `UserList`: Зв'язуюча таблиця для персональних списків читання (Читаю, В планах, тощо).
    - `Comment`, `Rating`: Соціальні взаємодії. Рейтинг включає складний об'єкт `ratingStats` для розподілу відсотків.
- **`routes/`**: Розділені API-ендпоінти, включаючи спеціалізовані маршрути агрегації (напр. `/api/users/profile/:username/analytics` та `/api/manga/home`).
- **`middleware/`**: Надійна система захисту `authMiddleware` (перевірка ролей, власників ресурсів).

## 4. Ключовий реалізований функціонал (Оновлено)

1.  **Просунута система рейтингів**: 
    - Автоматичний перерахунок середнього балу та відсоткового розподілу кожної оцінки (від 1 до 10).
    - Миттєве відображення результатів на фронтенді (гістограми в `MangaDetails`).
2.  **Персональні списки та Статистика**:
    - Можливість додавати тайтли у списки ("Читаю", "В планах", "Кинуто").
    - Бекенд агрегація: автоматичний підрахунок кількості коментарів, оцінок та прочитаних творів.
    - Візуальна аналітика: Графік активності (останні 7 днів) та лічильники прочитаних годин за допомогою `Recharts`.
3.  **Глобальний пошук та Каталог**:
    - `SearchOverlay`: "Живий" пошук із Debounce (затримкою) та підтримкою регулярних виразів на бекенді (нечутливий до регістру пошук за різними типами тайтлів).
    - Гнучкі фільтри в каталозі, що маплять кириличні назви інтерфейсу до англомовних статусів бази даних.
4.  **Управління контентом (CMS) та Модерація**: 
    - Повний CRUD з каскадним видаленням (видалення тайтлу автоматично видаляє всі його розділи).
    - Захист маршрутів видалення (тільки для авторів контенту або адмінів).
    - Динамічне відображення новинок, що обходить жорсткі фільтри модерації для миттєвого фідбеку авторам.

## 5. Поточний стан та досягнення

Проєкт перевершив стадію базового MVP і наближається до повноцінного продукту:
- **Синхронізація даних**: Відбувся успішний перехід від локального зберігання (localStorage) до повноцінних бекенд-моделей (UserList), що забезпечує безшовний досвід на різних пристроях.
- **UX/UI Полірування**: Вирішено проблеми з відображенням великих обкладинок (через CSS Grid `auto-fill`), налаштовано зручні попапи оцінювання та інтерактивні фільтри в профілі.
- **Безпека**: Жорстко розмежовано права доступу на рівні бекенду (можливість видаляти коментарі чи твори лише авторам або адмінам).

## 6. Рекомендації для подальшого розвитку

1.  **Розширення Аналітики**: Впровадження реальної бази даних історій переглядів (ReadingHistory) для заміни поточної імпровізованої математики в графіку "Останні 7 днів".
2.  **Оптимізація бази (Індекси)**: Додавання текстових індексів MongoDB для швидшого повнотекстового пошуку на великих об'ємах даних.
3.  **Сповіщення (WebSockets)**: Реалізація Socket.io для миттєвих сповіщень про відповіді на коментарі або вихід нових розділів для тайтлів зі списку "Читаю".
4.  **Пагінація (Pagination/Infinite Scroll)**: Додавання лімітів та пагінації для коментарів та сторінки каталогу для забезпечення стабільності при збільшенні бази даних.
