# Блок-схема алгоритму рольового захисту маршрутів

Ось код для PlantUML (використовуйте на [PlantUML.com](https://www.plantuml.com/plantuml/)):

```plantuml
@startuml
title Рис. 2.2.2 – Блок-схема алгоритму рольового захисту маршрутів

start

:Клієнт відправляє HTTP-запит на захищений маршрут;
:Запит потрапляє в middleware 'protect';

if (Header 'Authorization' містить 'Bearer token'?) then (так)
    :Вилучення JWT токена з заголовка;
    
    try
        :Верифікація токена за допомогою 'JWT_SECRET';
        :Декодування ID користувача з корисного навантаження (payload);
        :Пошук користувача в БД через User.findById(id);
        
        if (Користувач знайдений?) then (так)
            :Збереження об'єкта user у req.user;
            
            if (Маршрут потребує специфічної ролі? (напр. 'authorize')) then (так)
                if (Роль req.user.role відповідає дозволеній?) then (так)
                    :Виклик next() - перехід до контролера;
                    :Обробка запиту та відправка успішної відповіді;
                else (ні)
                    :Помилка 403: "Немає доступу для цієї ролі";
                endif
            else (ні)
                :Виклик next() - доступ дозволено (загальний 'protect');
            endif
            
        else (ні)
            :Помилка 401: "Користувача не знайдено";
        endif
        
    catch (TokenExpired/Invalid)
        :Помилка 401: "Токен недійсний або прострочений";
    end try

else (ні)
    :Помилка 401: "Авторизація відхилена, токен відсутній";
endif

stop
@enduml
```
